Messy inbound leads in. A clean Salesforce payload out.

GitHub ↗

The problem

Inbound lead lists are messy. Bad emails, duplicates, missing names and free text company fields. Sales can't prioritize until someone cleans and scores them.

How it works

01Ingest

Parse the CSV and validate every row with Zod.

02Normalize

Clean emails, phones, dates and companies. Drop bad emails and dedupe.

03Enrich

Call a mock company data API with retries, backoff and a cache.

04Score

26 JSON rules give each lead a score and a hot, warm or cold tier.

Results

100raw leads
89after cleaning and dedup
15hot leads
26scoring rules

Details

Scoring lives in a JSON file, so sales ops can change rules without touching code. Six runtime checks guard against silent data loss and stop the run if any one fails.

The output is a Salesforce Bulk API payload plus a flagged list for human review.

The written case study rebuilds what a production go to market pipeline could look like. It also maps how this batch job would grow into one.
